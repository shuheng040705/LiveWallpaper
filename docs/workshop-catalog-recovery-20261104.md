# Shadowrocket 配置模式下的创意工坊目录恢复

## 现场

用户截图中工坊目录与筛选栏同时为空，错误为 `The network connection was lost.`。这次失败发生在公开目录加载链路，不是 SteamCMD 下载过程。

确认系统 HTTP/HTTPS 代理使用本机 `127.0.0.1:1082`，Shadowrocket 当前为“配置”路由模式。经该代理读取 Steam 工坊 HTML 可成功，但加载官方 `cdn.fastly.steamstatic.com` 下的 SSR 脚本时出现多次连接中断；原版 URLSession 现场测试重现 NSURLErrorDomain -1005。后续同一官方脚本又可获取，因此证据说明存在间歇性断连，不能据此断言某条配置规则错误或所有节点都不可用。本次没有切换节点、改路由模式或改写配置文件。

## 修复

- 公开目录 GET 与只读查询 POST 对临时网络错误和部分 5xx 最多尝试 3 次，退避可取消；不对订阅事务套用此重试。
- 记录失败阶段、官方主机、错误域和代码；不记录 Cookie、搜索请求正文或代理凭据。
- 缓存已经发现的官方接口标识 24 小时，下次启动直接查询列表，减少对远端脚本的重复依赖；400/404 表示旧接口失效时重新发现一次。
- 从 HTML 获得筛选元数据后立即保存，不再等待后续脚本全部成功。
- 公开目录按搜索词、排序、标签/分级、页码、时间范围分别缓存，最多 32 页、最长 7 天；不把服务器订阅状态写入缓存。
- 原生界面先显示匹配当前查询的缓存并明确标记，再刷新网络结果。断连保留已有内容；切换查询不会误用上一查询的结果。
- 初次没有磁盘缓存时仍提供壁纸类型与内容分级基础筛选。网络错误改为中文提示。
- 分页失败后的“重试”只重试失败页，不把已加载页面清空。

## 验证

- 6 项恢复回归：脚本前两次断连后恢复、重启复用接口缓存、旧接口刷新、缓存查询隔离与去除订阅状态、取消退避、离线列表保留及分级隔离、分页重试（后两种模型路径分别覆盖）。
- Swift 全套：128 项，124 项通过，4 项需显式开启的外部网络验收默认跳过。
- 保持用户 Shadowrocket 配置不变，真实首页、分页、搜索和详情请求验收通过，耗时 5.465 秒。
- 应用缓存已实际保存目录页、筛选数据与官方接口信息；已部署并重启 `/Applications/LiveWallpaper.app`，核对开发包与安装包二进制一致；实际渲染确认筛选栏、壁纸卡片和订阅按钮恢复，网络错误横幅已消失。
